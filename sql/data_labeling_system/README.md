# 🏷️ Система разметки данных: Застройщики проектов

## 📋 Описание

3-ступенчатая система для разметки проектов, у которых отсутствует информация о застройщике (`developer_name_en IS NULL`).

## 🎯 Проблема

В таблице `unified_properties_table_full_light` есть проекты без указанного застройщика, что затрудняет:
- Анализ по застройщикам
- Фильтрацию проектов
- Интеграцию с таблицей `developers`

## 🔄 Решение

Создана система разметки из 3 этапов:

### **Этап 1: Идентификация** 🔍
Находит все проекты без застройщика и группирует их для анализа.

**Файл:** `01_identify_missing_developers.sql`

### **Этап 2: Разметка** ✏️
Создает таблицу для хранения разметки и позволяет заполнить информацию о застройщиках.

**Файл:** `02_labeling_template.sql`

### **Этап 3: Применение** ✅
Валидирует и применяет разметку к основной таблице.

**Файл:** `03_apply_labels.sql`

### 3. Заполнить разметку

Вручную или автоматически заполнить таблицу `project_developer_labeling`:
- `developer_name_en` - Название застройщика
- `developer_id` - ID застройщика (из таблицы developers)
- `confidence_level` - Уровень уверенности (HIGH, MEDIUM, LOW)
- `labeling_method` - Метод разметки (MANUAL, AUTOMATED, MATCHED)

```sql

```

## 📊 Пример запроса для начала работы

```sql
-- Найти проекты в Dubai Marina без застройщика
SELECT DISTINCT 
  building,
  project_name_en,
  project_id,
  district,
  COUNT(*) as properties_count
FROM `refty-409711.refty_looker_dashboard.unified_properties_table_full_light`
WHERE city = 'Dubai'
  AND isActive = true
  AND district = 'Dubai Marina'
  AND developer_name_en IS NULL
  AND project_id IS NOT NULL
GROUP BY building, project_name_en, project_id, district
ORDER BY properties_count DESC;
```

## 🔍 Методы разметки

### 1. MANUAL (Ручная)
- Разметка вручную экспертом
- Высокая точность
- Используется для сложных случаев

### 2. AUTOMATED (Автоматическая)
- Использование алгоритмов сопоставления
- Быстро, но требует валидации
- Используется для массовой разметки

### 3. MATCHED (Сопоставление)
- Сопоставление с существующими данными
- Использование fuzzy matching
- Средняя точность

---

## ✅ Уровни уверенности

- **HIGH**: Точное совпадение, проверено экспертом
- **MEDIUM**: Вероятное совпадение, требует проверки
- **LOW**: Предположение, обязательно требует проверки
